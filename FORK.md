# OpenClaw Fork — Source Install Documentation

This documents how OpenClaw runs from a forked source checkout on the Pi, how to make changes, rebuild, sync upstream updates, and roll back.

## Architecture

### What Changed

Previously, two separate npm installs existed:

- `~/.openclaw/lib/node_modules/openclaw/` — v2026.2.13 (gateway runtime, installed by onboarding)
- `~/.npm-global/lib/node_modules/openclaw/` — v2026.3.8 (CLI, installed via `npm i -g`)

Now, **both the gateway and CLI run from the same source checkout:**

- **Source repo:** `~/repos/openclaw/` (git clone of `alexjmiller5/openclaw` fork)
- **Upstream:** `openclaw/openclaw` (added as `upstream` remote)

### How It's Wired

**Gateway (systemd service):**

- The systemd override at `~/.config/systemd/user/openclaw-gateway.service.d/override.conf` points `ExecStart` at `~/repos/openclaw/dist/entry.js`
- Uses devbox's Node: `/home/openclaw/.local/share/devbox/global/default/.devbox/nix/profile/default/bin/node`
- The base service file (`~/.config/systemd/user/openclaw-gateway.service`) is generated by `openclaw gateway install` and gets rewritten on updates — but the override survives because systemd drop-in overrides are separate files

**CLI:**

- Linked globally via `pnpm link --global` from the repo
- The `openclaw` command at `~/.npm-global/bin/openclaw` is a symlink to the repo's `openclaw.mjs`
- Alternatively, run directly: `node ~/repos/openclaw/openclaw.mjs <command>`

**Old npm installs:**

- `~/.openclaw/lib/node_modules/openclaw/` still exists (v2026.2.13) but is no longer used
- `~/.npm-global/lib/node_modules/openclaw/` was the CLI, now superseded by pnpm link
- Both are safe to leave in place as fallbacks

### Key Files

| File                                                              | Purpose                             |
| ----------------------------------------------------------------- | ----------------------------------- |
| `~/repos/openclaw/`                                               | Source checkout (the fork)          |
| `~/repos/openclaw/dist/entry.js`                                  | Built gateway entrypoint            |
| `~/repos/openclaw/openclaw.mjs`                                   | CLI entrypoint                      |
| `~/repos/openclaw/rebuild.sh`                                     | Rebuild + restart script            |
| `~/.config/systemd/user/openclaw-gateway.service.d/override.conf` | systemd override pointing at source |
| `~/.openclaw/lib/node_modules/openclaw/`                          | Old npm install (fallback)          |

## Making Changes

### Quick Workflow

1. Edit source files in `~/repos/openclaw/src/`
2. Run `./rebuild.sh` (builds + restarts gateway)
3. Test
4. Commit and push

### Detailed Steps

```bash
cd ~/repos/openclaw

# 1. Make your edit
vim src/auto-reply/reply/dispatch-from-config.ts  # or whatever

# 2. Rebuild and restart
./rebuild.sh

# 3. If you only want to build (no restart):
./rebuild.sh --no-restart

# 4. If you also changed dependencies or UI:
./rebuild.sh --full

# 5. Commit
git add -A
git commit -m "fix: description of change"

# 6. Push (need auth token for alexjmiller5 fork)
TOKEN=$(bash ~/.openclaw/workspace/scripts/gh-app-token.sh)
git push https://x-access-token:${TOKEN}@github.com/alexjmiller5/openclaw.git
```

### What `rebuild.sh` Does

- `pnpm build` — compiles TypeScript to `dist/` via tsdown
- `systemctl --user daemon-reload` — picks up any override changes
- `systemctl --user restart openclaw-gateway` — restarts with new code
- Health check to confirm gateway came back up

With `--full`: also runs `pnpm install` + `pnpm ui:build`

### Pi Memory Gotchas

- `rebuild.sh` sets `NODE_OPTIONS=--max-old-space-size=2048` automatically
- `pnpm install` uses `--network-concurrency=1` in full mode to reduce memory
- If builds OOM, check what else is eating RAM: `ps aux --sort=-%mem | head -8`
- QEMU (Home Assistant VM) uses ~3GB alone — builds work if the Pi isn't overloaded

## Syncing Upstream Updates

When `openclaw/openclaw` releases a new version and you want to pull it in without losing your fork's changes:

### Rebase Workflow (Recommended)

```bash
cd ~/repos/openclaw

# 1. Make sure your working tree is clean
git status  # should show nothing to commit

# 2. Fetch upstream
git fetch upstream

# 3. Rebase your branch on top of upstream/main
git checkout fix/verbose-tool-summaries-in-groups  # or whatever branch
git rebase upstream/main

# 4. If there are conflicts:
#    - Edit the conflicted files
#    - git add <file>
#    - git rebase --continue
#    - If it's hopeless: git rebase --abort (goes back to before)

# 5. Rebuild
./rebuild.sh --full  # full because deps may have changed

# 6. Force-push (rebase rewrites history)
TOKEN=$(bash ~/.openclaw/workspace/scripts/gh-app-token.sh)
git push --force-with-lease https://x-access-token:${TOKEN}@github.com/alexjmiller5/openclaw.git
```

### If You Want to Stay on `main`

If you prefer keeping changes on main instead of a feature branch:

```bash
cd ~/repos/openclaw
git fetch upstream
git rebase upstream/main  # replays your commits on top of upstream
./rebuild.sh --full
```

### Checking What's New

```bash
# See upstream commits you don't have
git log HEAD..upstream/main --oneline

# See your commits that aren't in upstream
git log upstream/main..HEAD --oneline
```

## What About `openclaw update`?

**Be careful.** With a source install:

- `openclaw update` will try to `git pull --rebase` if the repo is clean. This is fine if you're tracking upstream, but may conflict with your patches.
- `openclaw gateway install --force` (run by the installer) rewrites the base systemd service file — **but your override survives**, so the gateway still points at your source checkout.
- `openclaw doctor` is safe to run — it does config migrations and health checks.

**Recommendation:** Don't use `openclaw update`. Use the manual rebase workflow above instead. You have full control.

## Current Fork Patches

### `fix/verbose-tool-summaries-in-groups` (2026-03-25)

**File:** `src/auto-reply/reply/dispatch-from-config.ts`

**Problem:** Tool summary messages (🛠️ Exec: ...) were unconditionally suppressed for all group chats via `ctx.ChatType !== "group"`. Forum topics are Telegram supergroups (chatType "group"), so they never got tool summaries even with verbose mode on.

**Fix:** Added verbose level check — if `verboseLevel` is "on" or "full" (from session entry or global `verboseDefault`), tool summaries are sent regardless of chat type:

```typescript
const effectiveVerboseLevel =
  sessionStoreEntry.entry?.verboseLevel ?? cfg.agents?.defaults?.verboseDefault;
const shouldSendToolSummaries =
  (ctx.ChatType !== "group" && ctx.CommandSource !== "native") ||
  effectiveVerboseLevel === "on" ||
  effectiveVerboseLevel === "full";
```

## Rollback to npm Install

If the source install breaks and you need to go back:

```bash
# 1. Revert the systemd override to point at the old npm install
cat > ~/.config/systemd/user/openclaw-gateway.service.d/override.conf << 'EOF'
[Service]
OOMScoreAdjust=0
ExecStart=
ExecStart=/home/openclaw/.local/share/devbox/global/default/.devbox/nix/profile/default/bin/node /home/openclaw/.openclaw/lib/node_modules/openclaw/dist/entry.js gateway --port 18789
Environment="PATH=/home/openclaw/.local/share/devbox/global/default/.devbox/nix/profile/default/bin:/home/openclaw/.local/bin:/home/openclaw/.npm-global/bin:/usr/local/bin:/usr/bin:/bin"
EOF

# 2. Unlink the CLI
cd ~/repos/openclaw && pnpm unlink --global

# 3. Reinstall the CLI via npm
npm i -g openclaw@latest

# 4. Restart
systemctl --user daemon-reload
systemctl --user restart openclaw-gateway

# 5. Verify
openclaw status
```

The old npm install at `~/.openclaw/lib/node_modules/openclaw/` is still there (v2026.2.13), so rollback is instant — no download needed.

## Troubleshooting

### Gateway won't start after rebuild

```bash
# Check logs
journalctl --user -u openclaw-gateway --since "1 min ago" --no-pager

# Verify dist/entry.js exists
ls -la ~/repos/openclaw/dist/entry.js

# Check the override is correct
systemctl --user cat openclaw-gateway | head -30
```

### Build OOMs

```bash
# Check memory
free -m

# Kill memory hogs temporarily, or just retry when the Pi is less loaded
./rebuild.sh
```

### pnpm not found

```bash
# pnpm is at ~/.npm-global/bin/pnpm
export PATH="$HOME/.npm-global/bin:$PATH"

# Or run directly
~/.npm-global/bin/pnpm install
```

### Push fails (auth)

```bash
# Generate a fresh GitHub App token
TOKEN=$(bash ~/.openclaw/workspace/scripts/gh-app-token.sh)
git push https://x-access-token:${TOKEN}@github.com/alexjmiller5/openclaw.git
```
